# BND005: Unity のデシリアライズ後に ViewModel の状態が未初期化になる可能性があります

## メッセージ

> フィールド '{0}' は ViewModel 型 '{1}' に [{2}] を使用しています。型に [Serializable] が付与されていても、Unity のデシリアライズ後に生成されたランタイム状態が未初期化になる可能性があります。ViewModel は実行時に構築または代入してください。

`{0}` はフィールド、`{1}` はそのViewModel型、`{2}` はシリアライズ属性です。

## 原因

宣言型に `[ViewModel]` が付いたフィールドに、Unityの `[SerializeField]` または `[SerializeReference]` を付与しています。Unityのデシリアライズでは、生成されたPublisherなどの実行時依存関係の初期化を保証できません。

## 違反例

```csharp
public class ScreenEntry : MonoBehaviour
{
    [SerializeReference]
    private CounterViewModel _viewModel;
}
```

## 修正例

ViewModelを実行時に構築・代入します。Requiredメンバーを持たないViewModelの場合は次のようにします。

```csharp
public class ScreenEntry : MonoBehaviour
{
    [SerializeField]
    private Binder _binder;

    private void Start()
    {
        var viewModel = new CounterViewModel(_binder);
        _binder.Initialize(viewModel);
        _binder.Run();
    }
}
```

VContainerの登録でもViewModelを構築・初期化できます。生成された実行時状態の復元をUnityに任せるのではなく、ViewModelの構築に必要なデータをシリアライズしてください。

## 対象範囲と例外

- フィールドの宣言型自体が、実際のBindingsの `[ViewModel]` を直接付与した名前付き型である場合が対象です。配列・型パラメーター・フィールド以外・他の型のフィールドは対象外です。
- 対象フィールドのシリアライズ属性ごとに、その属性位置へ警告を報告します。
- 生成コードは対象外です。フレームワークの型や属性は単純名ではなく、シンボルの同一性で識別します。
- ViewModelへの `[System.Serializable]` の明示だけでは診断しません。独自シリアライズなどを許容するためであり、Unityによる永続化のサポートを意味しません。
- `[System.Serializable]` を付けても、ViewModel型のシリアライズ対象フィールドへの警告はなくなりません。ジェネレーターは通常、この属性を `UNITY_EDITOR` のときだけ付与し、明示済みの場合は重複付与しません。
