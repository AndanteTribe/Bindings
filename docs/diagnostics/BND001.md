# BND001: ViewModel type name must end with "ViewModel", optionally followed by ASCII digits

English | [日本語](BND001.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Type '{0}' is annotated with [ViewModel] but its name does not end with "ViewModel", optionally followed by ASCII digits (0-9). No source will be generated for this ViewModel.

`{0}` is the annotated type name.

## Cause

A class or struct annotated with `[ViewModel]` has a name that does not end with case-sensitive `ViewModel`, optionally followed by ASCII digits (`0`–`9`). The generator replaces only that final `ViewModel` with `View` and preserves the digits.

## Violation

```csharp
[ViewModel]
public partial class Counter { }
```

## Fix

End the type name with `ViewModel`, optionally followed by ASCII digits:

```csharp
[ViewModel]
public partial class CounterViewModel { }
```

This produces `CounterView`. `CounterViewModel2` produces `CounterView2`, and `CounterViewModel12` produces `CounterView12`. `CounterViewModelExtra`, `CounterViewModel2Extra`, and names ending in non-ASCII digits do not follow the convention. Update references to the renamed type as needed.

## Scope and generation

The diagnostic is reported at the annotated type declaration. Neither its ViewModel source nor its View source is generated. Other ViewModels can still be generated. This rule is reported by the source generator, rather than the usage analyzer.
