# BND001: ViewModel type name must contain "ViewModel"

English | [日本語](BND001.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Type '{0}' is annotated with [ViewModel] but its name does not contain "ViewModel". No source will be generated for this ViewModel.

`{0}` is the annotated type name.

## Cause

A class or struct annotated with `[ViewModel]` has no case-sensitive `ViewModel` substring in its name. The generator derives the View name by replacing every `ViewModel` occurrence with `View`; the substring does not have to be a suffix.

## Violation

```csharp
[ViewModel]
public partial class Counter { }
```

## Fix

Include `ViewModel` in the type name:

```csharp
[ViewModel]
public partial class CounterViewModel { }
```

This produces `CounterView`. `CountViewModel1` similarly produces `CountView1`. Update references to the renamed type as needed.

## Scope and generation

The diagnostic is reported at the annotated type declaration. Neither its ViewModel source nor its View source is generated. Other ViewModels can still be generated. This rule is reported by the source generator, rather than the usage analyzer.

See [generated-code conventions](../../README.md#generated-code-conventions) for containing types and generated file names.
