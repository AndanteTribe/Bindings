# BND004: Unsupported type accessibility

English | [日本語](BND004.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Type '{0}' has unsupported accessibility '{1}'. No source will be generated for ViewModel '{2}'.

`{0}` is the unsupported type, `{1}` is its Roslyn accessibility, and `{2}` is the affected ViewModel.

## Cause

The generator cannot express the declared accessibility of a `[ViewModel]` type or one of its containing types. It reproduces those declarations when emitting both the ViewModel and the View.

| Roslyn accessibility | Generated keyword |
| --- | --- |
| `Private` | `private` |
| `ProtectedAndInternal` | `private protected` |
| `Protected` | `protected` |
| `Internal` | `internal` |
| `ProtectedOrInternal` | `protected internal` |
| `Public` | `public` |

`NotApplicable` and unknown accessibility values are unsupported. This diagnostic also protects against unexpected or error symbols.

## How to fix

Inspect the named type and any C# compiler errors. Use valid C# declarations whose accessibility can be represented by the table above. For example, this nested declaration is supported:

```csharp
public partial class Screen
{
    [ViewModel]
    private partial class CounterViewModel { }
}
```

The generated `CounterView` is also private and nested in `Screen`. All containing types must be partial, but a missing `partial` modifier is a separate C# compiler issue, not a BND004 condition. Likewise, an accessibility that is invalid at the top level is left to the compiler when Roslyn still supplies a supported value.

## Generation

The diagnostic identifies the unsupported type's source location when available. Neither source is generated for the affected ViewModel; other ViewModels can still be generated. The generator reports the problem instead of failing the entire generation pass with an exception.
