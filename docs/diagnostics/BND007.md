# BND007: Schema fields must be accessed through generated properties

English | [日本語](BND007.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |

## Message

> Field '{0}' is annotated with [Schema]. Access the generated property '{1}' instead of the field.

`{0}` is the Schema field and `{1}` is its generated property name.

## Cause

User code directly references a `[Schema]` field declared in a type directly annotated with `[ViewModel]`. Generated property setters publish rebind requests; direct field writes bypass that behavior. Reads must also use the generated property.

## Violation

```csharp
[ViewModel]
public partial class CounterViewModel
{
    [Schema(PathResolver.TMPro.TMP_Text.text)]
    private int _count;

    public void Increment() => _count++;
}
```

## Fix

Use the generated property:

```csharp
public void Increment() => Count++;
```

Property names remove leading underscores and then an `m_` prefix, and uppercase the first remaining character: `_count`, `__count`, and `m_count` all map to `Count`. See [generated-code conventions](../../README.md#generated-code-conventions).

## Scope and exceptions

- Reads, assignments, compound assignments, increments/decrements, `ref`/`out`/`in` arguments, and ref locals are checked, regardless of field accessibility.
- Constructors, user-written accessors, lambdas, local functions, nested types, partial declarations, and external references to accessible fields are included.
- Each field-reference expression receives one diagnostic. Only fields declared in a directly annotated ViewModel qualify; methods with Schema, unannotated fields, and Schema fields outside ViewModels do not.
- Generated code, including generated getter/setter bodies, is excluded. `nameof(_count)` is allowed because it does not access the field value.
- A declaration initializer such as `private int _count = 1;` is allowed. References to other Schema fields inside an initializer expression are still checked.

## Fixing non-trivial accesses

There is no automatic Code Fix. A normal property cannot replace every field reference directly. For `ref`/`out` operations or mutation of a struct-valued field's members, use an appropriate local value and assign the final value back through the property when needed. Preserve the original operation's behavior.

Avoid redundant manual rebind notifications after a generated setter. During construction, initialize the publisher before invoking setters; the generated class-only `OnPostConstruct` hook runs after all Required members and the publisher are assigned.

## Generation

Source generation continues so the suggested property remains available. The diagnostic remains an Error even when the fix requires restructuring.
