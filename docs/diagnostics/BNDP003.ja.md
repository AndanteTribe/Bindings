# BNDP003: ViewModel は他の ViewModel を集約するだけにしないでください

## メッセージ

> ViewModel '{0}' は子 ViewModel メンバー '{1}' を保持または公開するだけです。所有する ViewModel 自身の処理で利用しないのであれば、所有をこの ViewModel の外へ移してください。

`{0}` は所有者、`{1}` は子を保持するメンバーです。

## 原因

ViewModelが別のViewModelを保持していますが、自身の処理で利用していません。子インスタンスをまとめたり、そのまま公開したりするだけの場合は、外部の所有者へ移します。

## 違反例

`ChildViewModel` がIViewModelを実装している前提です。

```csharp
[ViewModel]
public partial class ParentViewModel
{
    [Required]
    private readonly ChildViewModel _child;

    public ChildViewModel Child => _child;
}
```

コンストラクター注入と、そのまま公開するgetterは、処理での利用には数えません。

## 修正例

親に不要な保持を削除し、外部の構築処理で所有・配布します。例えば、独立して構築した親・子ViewModelを、それぞれBinderに登録できます。

```csharp
binder.Initialize(parent);
binder.Initialize(child);
```

親の処理が実際に子を必要とする場合は、所有を維持できます。その処理で子のメソッドを呼ぶ、状態を読み書きする、別の操作へ渡す、といった参照は利用に数えます。

## 保持メンバーと別名

- 所有者と子は、実際の `Bindings.IViewModel`・継承経由の実装・制約付き型パラメーターで識別します。メンバーの宣言型がIViewModelそのものでも対象です。
- 明示的に宣言されたインスタンスフィールドと自動プロパティを、個別の保持先として扱います。未使用の保持メンバーごとに1回報告します。
- 保持先をそのまま返す式形式・return文1つのgetterを別名として扱います。別名の連鎖と生成Schemaプロパティも含み、別名に対する重複診断はしません。
- staticメンバー・インデクサー・コレクション・継承した保持メンバー・保持先をそのまま公開しない計算プロパティは、保持先の検査対象外です。

## 利用として数える参照

所有者自身の宣言した処理から、その所有インスタンスを通じて参照する必要があります。partial宣言・ラムダ・ローカル関数を含みます。値の変換は必要ありません。

次は利用に**数えません**。

- コンストラクター注入・setterを含む単純代入の代入先。
- そのまま返すgetterと `nameof`。
- 別の所有者インスタンス経由、外部の利用者、ネストした補助型からの参照。

生成コードも手書きコードと同様に解析・報告します。Requiredの生成コンストラクターによる代入は利用に数えませんが、生成コード内での実際の処理上の参照は利用に数えます。到達可能性やプログラム全体のデータフローではなく、参照を解析する規則です。

## ソース生成と設定

ソース生成は継続します。既定の重大度はErrorで、修正・抑制・重大度の変更を行うまでコンパイルは失敗します。所有権の移動には設計判断が必要なため、自動Code Fixはありません。
