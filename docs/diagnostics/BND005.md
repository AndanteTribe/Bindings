# BND005: Unity deserialization may leave ViewModel state uninitialized

English | [日本語](BND005.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | None |

## Message

> Field '{0}' uses [{2}] with ViewModel type '{1}'. Unity deserialization may leave generated runtime state uninitialized, even when the type is marked [Serializable]. Construct or assign the ViewModel at runtime instead.

`{0}` is the field, `{1}` is its ViewModel type, and `{2}` is the serialization attribute.

## Cause

A field whose declared type has `[ViewModel]` uses Unity's `[SerializeField]` or `[SerializeReference]`. Unity deserialization does not guarantee initialization of generated runtime dependencies such as the publisher.

## Violation

```csharp
public class ScreenEntry : MonoBehaviour
{
    [SerializeReference]
    private CounterViewModel _viewModel;
}
```

## Fix

Construct or assign the ViewModel at runtime. For a ViewModel with no Required members:

```csharp
public class ScreenEntry : MonoBehaviour
{
    [SerializeField]
    private Binder _binder;

    private void Start()
    {
        var viewModel = new CounterViewModel(_binder);
        _binder.Initialize(viewModel);
        _binder.Run();
    }
}
```

VContainer registration is another supported way to construct and initialize ViewModels. Serialize the data needed to construct a ViewModel rather than relying on Unity to restore the ViewModel's generated runtime state.

## Scope and exceptions

- The declared field type itself must be a named type directly annotated with the actual Bindings `[ViewModel]` attribute. Arrays, type parameters, non-field targets, and fields of other types are outside this rule's scope.
- Each matching serialization attribute on each matching field reports a warning at that attribute.
- Generated code is excluded. Framework types and attributes are matched by symbol identity, not their simple names.
- A user-written `[System.Serializable]` on the ViewModel alone does not cause this diagnostic. This permits other serialization mechanisms; it does not establish support for Unity persistence.
- Adding `[System.Serializable]` does not suppress a warning on a serialized ViewModel field. The generator normally adds that attribute only under `UNITY_EDITOR`, and does not duplicate an explicit attribute.
