# BND002: Invalid [Schema] id value

English | [日本語](BND002.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> [Schema] id value {0} is invalid. Use id >= 0 for explicit grouping, or omit id (defaults to -1) for auto-numbering.

`{0}` is the invalid ID.

## Cause

A `[Schema]` on a field or method specifies an `id` less than `-1`.

## Violation

```csharp
[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: -2)]
public void Submit() { }
```

## Fix

Omit `id` for an independent component, or use a non-negative ID for explicit sharing:

```csharp
[Schema(PathResolver.UnityEngine.UI.Button.onClick)]
public void Submit() { }

[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0)]
public void Accept() { }

[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0)]
public void Confirm() { }
```

Here `Accept` and `Confirm` share one Button; `Submit` uses another.

## Component sharing

- Sharing requires both the same component type and the same non-negative ID. The ID alone does not group different component types.
- Each `id = -1` entry is independent, including repeated attributes on one member. Omitting `id` is equivalent to specifying `-1`.
- The ID is not directly appended to the generated field name. See [component fields and sharing](../../README.md#component-fields-and-sharing).

## Generation

The generator reports this diagnostic at each invalid attribute and treats its ID as `-1` to avoid cascading errors. Both sources are still generated unless another diagnostic prevents generation. The default Error severity still fails compilation.
