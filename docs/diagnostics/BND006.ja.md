# BND006: View の実装は MonoBehaviour を継承できません

[English](BND006.md) | 日本語

| 項目 | 内容 |
| --- | --- |
| カテゴリ | Bindings |
| 標準重大度 | Error |
| 既定で有効 | はい |

## メッセージ

> 型 '{0}' は Bindings.IView を実装し、UnityEngine.MonoBehaviour を継承しています。View の実装は MonoBehaviour を継承できません。

`{0}` はViewの型です。

## 原因

実際の `Bindings.IView` を実装したクラスが、`UnityEngine.MonoBehaviour` を継承しています。ViewはBinderへ登録する通常のC#オブジェクトであり、UnityのコンポーネントとしてのライフサイクルはBinderが担当します。

## 違反例

`CounterViewModel` から `CounterView` が生成される場合、次のユーザー側のpartial宣言は不正です。

```csharp
public sealed partial class CounterView : MonoBehaviour
{
}
```

生成されたpartial宣言が `IView<CounterViewModel>` を実装するため、結合した型は診断条件に該当します。

## 修正例

Viewを通常のクラスにします。

```csharp
public sealed partial class CounterView
{
    partial void OnPostBind()
    {
        // Perform work after binding.
    }
}
```

ViewをBinderのViewsリストに登録します。必要なUnityライフサイクルコールバックは別のコンポーネントへ配置してください。IViewの手動実装でもMonoBehaviourを継承できません。

## 対象範囲とソース生成

- 抽象クラス・ネスト型・`IView<T>`・継承経由のインターフェイス実装・間接的なMonoBehaviour継承も対象です。
- Usage Analyzerが型ごとに1回、ソースの型識別子へ報告します。partial宣言は1つの型として扱います。
- 生成された宣言自体は診断しませんが、そのインターフェイスによってユーザー側のpartial宣言が不正になる場合があります。
- ソース生成は継続します。ただし、既定の重大度はErrorのため、コンパイルは失敗します。
