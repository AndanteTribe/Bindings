# BNDP004: 生成された Schema プロパティへの代入をラッパーメソッドにしないでください

[English](BNDP004.md) | 日本語

| 項目 | 内容 |
| --- | --- |
| カテゴリ | Bindings.Practices |
| 標準重大度 | Error |
| 既定で有効 | はい |
| Code Fix | なし |

## メッセージ

> メソッド '{0}' は引数を公開された書き込み可能な Schema プロパティにそのまま代入するだけです。プロパティへ直接代入してください。

`{0}` はラッパーメソッド名です。

## 原因

ViewModelのメソッドが、引数を自分自身の異なる公開Schemaプロパティへ、そのまま代入するだけになっています。プロパティ自体が、再バインド通知を含む公開更新APIをすでに提供しています。

## 違反例

```csharp
[ViewModel]
public partial class CounterViewModel
{
    [Schema(PathResolver.TMPro.TMP_Text.text)]
    private int _count;

    public void SetCount(int count) => Count = count;
}
```

## 修正例

重複するラッパーを削除し、呼び出し側でプロパティに代入します。

```csharp
viewModel.Count = count;
```

検証・変換などの実際の処理を行うメソッドは、この単純コピー条件の対象外です。意味のある操作は適切な場所に残してください。

## メソッドの条件

- 所属する型が、実際の `Bindings.IViewModel` を実装していること。継承経由の実装も含みます。
- 通常の非static・非async・void戻り値のメソッドで、引数が1つ以上あること。すべてのアクセシビリティを検査します。
- override・明示的または暗黙的なインターフェイス実装（ジェネリックを含む）・実際の `[Schema]` 属性を持つメソッドは除外します。partialメソッドの宣言側・実装側の属性やインターフェイス実装も考慮します。
- デリゲートやメソッドグループとしての使用は免除条件になりません。

## 代入の条件

- 全引数をそれぞれ異なるプロパティへ正確に1回ずつコピーし、未使用の引数がないこと。`ref`・`in`・`out` 引数は除外します。
- プロパティが現在のインスタンス（`this`・無修飾・`base`）に属し、publicかつpublicの非init setterを持つこと。子や別インスタンスへの代入は対象外です。
- プロパティ名と型が、そのプロパティの所属型で宣言したSchemaフィールドの生成名・型に対応すること。通常のプロパティ・フィールド直接書き込み・staticプロパティ・インデクサー・getterのみ・非公開setterは対象外です。
- 引数とプロパティの型が、nullable参照型注釈も含め一致すること。括弧は許可します。同じ型へのキャストも含め、明示的・暗黙的な変換があれば報告しません。
- 本体全体が、引数ごとに1つの単純代入式文だけで構成されること。式形式のメソッドにも対応します。明示的なreturn・ローカル宣言・呼び出し・制御フロー・複合代入・引数やプロパティの重複がある場合は報告しません。

## 報告とソース生成

メソッド識別子に1件報告します。生成コードも手書きコードと同様に解析・報告します。ソース生成は継続しますが、既定の重大度はErrorのため、修正・抑制・重大度の変更を行うまでコンパイルは失敗します。

APIの削除と呼び出し側の更新には明示的な判断が必要なため、自動Code Fixはありません。
