# BND003: Conflicting tooltip values for the same View field

English | [日本語](BND003.ja.md)

| Property | Value |
| --- | --- |
| Category | Bindings |
| Default severity | Error |
| Enabled by default | Yes |
| Code fix | None |

## Message

> View field '{0}' has conflicting tooltip values from multiple [Schema] entries with the same id. Only the first tooltip will be used.

`{0}` is the generated component field name.

## Cause

Schema entries sharing one View component field specify different non-empty tooltips. Sharing requires the same component type and the same non-negative ID.

## Violation

```csharp
[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0, tooltip: "Accept")]
public void Accept() { }

[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0, tooltip: "Confirm")]
public void Confirm() { }
```

Both methods use `_acceptButton`, but disagree on its tooltip.

## Fix

Specify the shared tooltip once, or use exactly the same text on every entry:

```csharp
[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0, tooltip: "Accept and confirm")]
public void Accept() { }

[Schema(PathResolver.UnityEngine.UI.Button.onClick, id: 0)]
public void Confirm() { }
```

If these are separate components, give them different IDs or omit both IDs instead.

## Selection and generation

- The first non-empty tooltip wins. Fields are collected before methods, in their respective declaration order.
- Empty tooltips do not conflict; identical non-empty values do not conflict either.
- Entries with `id = -1` are independent, so their tooltips cannot conflict with each other.
- A Unity `Tooltip` attribute is emitted before `SerializeField` on the component field.
- The generator reports once per conflicting View field, without a source location, and continues generating both sources using the first non-empty value. The default Error severity still fails compilation.
